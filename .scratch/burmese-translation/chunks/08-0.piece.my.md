## Week 6 — Agentic Code Review

**Focus:** AI ကုဒ်ရီဗျူး (code review) သည် မည်သည့်အရာများကို ကောင်းစွာဖမ်းထုတ်နိုင်ပြီး မည်သည့်အရာများကို လွဲမှားတတ်သည်၊ စစ်ဆေးသူ (reviewer) ဗိသုကာများနှင့် စိတ်ကြိုက်ပြင်ဆင်ထားသော စည်းမျဉ်းများ၊ AI ကုဒ်ရီဗျူးကို အဖွဲ့၏ ပူးလ်ရီကွက်စ် (pull request) လုပ်ငန်းစဉ် (workflow) တွင် ထည့်သွင်းအသုံးပြုခြင်း။

### အခြေခံကျသော သင်ခန်းစာ (core material) (≈ 3 h 30 min)

1. **Canonical guide:** Google, [Engineering Practices: Code Review⟦U110⟧ နှင့် [Reviewer Guide⟦U111⟧ (60 min)။
2. **Free book chapter:** *Software Engineering at Google*, [Chapter 9: Code Review⟦U112⟧ (45 min)။
3. **Talk:** Graphite မှ Tomas Reimers, [AI-powered entomology: lessons from millions of AI code reviews⟦U113⟧ (10 min), Graphite ၏ ရေးသားထားသော [AI code review implementation and best practices⟦U114⟧ (20 min) နှင့်အတူ။
4. **Review architecture:** Ankit Jain, [How to Kill the Code Review⟦U115⟧ (16 min) — စပက် (specification) များ၊ ပြန်လည်အသုံးပြုနိုင်သော ဘေးကင်းလုံခြုံရေး ထိန်းကွပ်ချက် (guardrail) များ၊ ရလဒ်သေချာသော စစ်ဆေးမှု (deterministic check) များ၊ အကောင်အထည်ဖော်ဆောင်ရွက်နိုင်သော စမ်းသပ်မှုအစီအစဉ်များ၊ စမ်းသပ်ကြည့်ရှုမှုများနှင့် လူကိုယ်တိုင် ညှိနှိုင်းဆောင်ရွက်မှုတို့ကို ပေါင်းစပ်ထားသည့် ငါးလွှာပါဝင်သော ယုံကြည်စိတ်ချရမှု ပုံစံ။
5. **What automation cannot replace:** Geoffrey Litt, [Understanding Is the New Bottleneck⟦U116⟧ (20 min) — ကုဒ်မှန်ကန်မှုကို စစ်ဆေးခြင်းသက်သက်မဟုတ်ဘဲ ဗိသုကာဆိုင်ရာ နားလည်သဘောပေါက်မှု၊ လမ်းညွှန်သင်ပြမှုနှင့် ပေါင်းစပ်ညှိနှိုင်းမှုဆိုင်ရာ ရီဗျူးအဖြစ် ရှုမြင်ခြင်း။
6. **Integrations:** GitHub, [About GitHub Copilot code review⟦U117⟧ (15 min) နှင့် Anthropic, [Claude Code GitHub Actions⟦U118⟧ (15 min) — ပူးလ်ရီကွက်စ်တစ်ခုတွင် စစ်ဆေးသူ ကိုယ်စားလှယ် (agent) ထည့်သွင်းသည့် အသုံးအများဆုံး နည်းလမ်းနှစ်ခု။

### Build

ပြင်းထန်မှုအလိုက် စီစဉ်ထားသော ရီဗျူးစံနှုန်းသတ်မှတ်ချက်ကို ဖန်တီးပါ- မှန်ကန်မှု၊ လုံခြုံရေး၊ အချက်အလက် ဆုံးရှုံးမှု၊ ပြိုင်တူလုပ်ဆောင်နိုင်စွမ်း၊ ကိုက်ညီဆီလျော်မှု၊ စမ်းသပ်မှုများ၊ ထိန်းသိမ်းရလွယ်ကူမှု၊ ထို့နောက် အရေးအသားပုံစံ။ စစ်ဆေးသူ ကိုယ်စားလှယ်ကို အတိအကျလိုင်းများကို ကိုးကားရန်၊ ပျက်ကွက်မှုဖြစ်စဉ်ကို ရှင်းပြရန်နှင့် အသေးငယ်ဆုံး ပြင်ဆင်မှုကို အဆိုပြုရန် တောင်းဆိုပါ။ ပြောင်းလဲမှုကို ရေးသားခဲ့ခြင်းမရှိသော မော်ဒယ် (model)/ဆရှင် (session) ကို အသုံးပြုပါ။ အထက်ပါ ချိတ်ဆက်မှုတစ်ခုခုကို အသုံးပြု၍ သင်၏ ပူးလ်ရီကွက်စ်များနှင့် ချိတ်ဆက်ပါ။

စစ်ဆေးသူကို အနည်းဆုံး ပူးလ်ရီကွက်စ် ငါးခုတွင် အကဲဖြတ်ပါ (evaluation)၊ သိမ်မွေ့သော ဘဂ်များ ရည်ရွယ်ချက်ရှိရှိ ထည့်သွင်းထားသည့် ပူးလ်ရီကွက်စ် တစ်ခုပါဝင်သည်။ မှတ်ချက်တိုင်းကို true positive၊ false positive၊ duplicate သို့မဟုတ် low-value ဟု အမှတ်အသားပြုပါ။ လက်ခံအသုံးပြုမှု (adoption) နှုန်းနှင့် လွတ်ကင်းသွားသော ချို့ယွင်းချက်များကို ခြေရာခံပါ။ လူတစ်ဦးသည် မာ့ချ် (merge) အတည်ပြုချက် (approval) ကို ပိုင်ဆိုင်ဆဲဖြစ်သည်။

### ပြီးစီးမှု သတ်မှတ်ချက်များ (done when)

- စံနှုန်းသတ်မှတ်ချက်ကို စစ်ဆေးပြီးဖြစ်၍ စစ်ဆေးသူ ကိုယ်စားလှယ်သည် ပူးလ်ရီကွက်စ်များတွင် အလိုအလျောက် အလုပ်လုပ်သည်။
- စစ်ဆေးပြီးသော ပူးလ်ရီကွက်စ် ငါးခုတွင် မှတ်ချက်တိုင်းကို အမှတ်အသားပြုထားပြီး တိကျမှုကို တွက်ချက်ထားသည်။
- ရည်ရွယ်ချက်ရှိရှိ ထည့်သွင်းထားသော ဘဂ်ပါသည့် ပူးလ်ရီကွက်စ် အစီရင်ခံစာတွင် မည်သည့် ဘဂ်များကို ဖမ်းမိပြီး မည်သည့် ဘဂ်များ လွတ်ကင်းသွားသည်ကို ဖော်ပြထားသည်။
- စာပိုဒ်တစ်ပိုဒ်တွင် စစ်ဆေးသူ စနစ်တကျ လွဲမှားတတ်သည့် အရာများနှင့် ယခုအခါ မည်သည့် ရလဒ်သေချာသော စစ်ဆေးမှုက ၎င်းကို လွှမ်းခြုံထားကြောင်း မှတ်တမ်းတင်ထားသည်။
