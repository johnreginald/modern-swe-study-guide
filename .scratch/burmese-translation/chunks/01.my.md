## How to use this guide

**တစ်ပတ်လျှင် 10–12 နာရီ** ဖယ်ထားရန် စီစဉ်ပါ။ ၎င်းကို ယခုကဲ့သို့ ခွဲဝေပါ-

- 3–4 နာရီ: ထိုရက်သတ္တပတ် (week) အတွက် **အခြေခံကျသော သင်ခန်းစာ (Core material)**။ ရက်သတ္တပတ်တစ်ခုစီ၏ core စာရင်းကို လေးနာရီဝန်းကျင်တွင် ကန့်သတ်ထားပြီး ကြာမြင့်ချိန်များကို အကြောင်းအရာတစ်ခုစီ၏ ဘေးတွင် ရေးသားထားသည်။
- 5–6 နာရီ: အပတ်စဉ် **အကောင်အထည်ဖော် ရေးသားခြင်း (Build)**။
- 1–2 နာရီ: ရလဒ်များ၊ မအောင်မြင်မှုများ၊ ကုန်ကျစရိတ် (cost) များနှင့် ရရှိခဲ့သော သင်ခန်းစာများကို မှတ်တမ်းတင်ပြီး ထိုရက်သတ္တပတ်၏ **ပြီးစီးမှု သတ်မှတ်ချက်များ (Done when)** စာရင်းကို အမှန်ခြစ်ပါ။

**ပိုမိုနက်ရှိုင်းသော သင်ခန်းစာ (Deeper material)**၊ **မဖြစ်မနေကြည့်ရှုရန် မလိုသော ဗီဒီယိုလမ်းကြောင်း** နှင့် **ကိရိယာများ နှင့် ကိုးကားချက်များ** အောက်ရှိ အရာအားလုံးသည် ရွေးချယ်နိုင်သော (optional) များ ဖြစ်ကြသည်။ စိတ်ပါဝင်စားမှုအပေါ် မူတည်၍ ရွေးချယ်ပါ၊ အကုန်လုံးပြီးအောင် လုပ်ရန် မကြိုးစားပါနှင့်။

ဆယ်ပတ်လုံးလုံးတွင် အလတ်စား ရီပို (repository) တစ်ခုကို အသုံးပြုပါ။ UI၊ စမ်းသပ်မှုများ (tests) နှင့် CI ပါဝင်သော လတ်ဆတ်သည့် SaaS အက်ပ်၊ ဒေဗလော့ပါ ကိရိယာ (tool) သို့မဟုတ် API တစ်ခုသည် သီးခြားစီဖြစ်နေသော ကစားစရာ စီမံကိန်း ဆယ်ခုထက် ပိုမိုထိရောက်သည်။ ရက်သတ္တပတ်တိုင်းတွင် ထိုစနစ်တစ်ခုတည်းကိုပင် ပိုမိုကောင်းမွန်အောင် ပြုလုပ်သင့်သည်။

အတောင့်တင်းဆုံး အခမဲ့ အခြေခံသင်ခန်းစာမှာ Hugging Face ၏ [Context Course⟦U2⟧ (သင်ခန်းစာများ- Agent Skills, MCP, Plugins, Sub-agents, Hooks နှင့် Bonus ဖြစ်သော Nano Harness) ဖြစ်သည်။ ၎င်းသည် ဤလမ်းညွှန်၏ ပထမဝက်နှင့် ပုံမှန်မဟုတ်ဘဲ အလွန်ပင် ကိုက်ညီမှုရှိသည်။ ပိုမိုနက်ရှိုင်းစေရန်နှင့် တိုးချဲ့ရန် အောက်ပါ သင်ခန်းစာများကို အသုံးပြုပါ။

ဤလမ်းညွှန်သည် မည်သည့် ပရိုဂရမ်းမင်းဘာသာစကားအပေါ်မျှ အခြေမခံပါ၊ ဥပမာအများစုသည် Python သို့မဟုတ် JavaScript ကို အသုံးပြုထားသည်။ သင့်အနေဖြင့် ခိုင်မာသော ပရိုဂရမ်းမင်း အတွေ့အကြုံ (တက္ကသိုလ်အဆင့် သင်တန်း နှစ်ခု သို့မဟုတ် သုံးခု သို့မဟုတ် ၎င်းနှင့် ညီမျှသော အတွေ့အကြုံ) ရှိရန် လိုအပ်သည်။ စက်သင်ယူခြင်း (machine learning) နောက်ခံရှိပါက ပိုမိုအထောက်အကူပြုသော်လည်း မဖြစ်မနေ လိုအပ်သည်တော့ မဟုတ်ပါ၊ အကယ်၍ transformers များကို သင် မရင်းနှီးသေးပါက Week 1 optional foundation တွင် ၎င်းလိုအပ်ချက်ကို ဖြည့်ဆည်းပေးထားသည်။

### Tooling and budget

အချို့သော ကိရိယာများသည် စာရင်းသွင်းမှု သို့မဟုတ် API key တစ်ခု လိုအပ်သည်။ Week 1 မစတင်မီ ဤအချက်ကို ဆုံးဖြတ်ပါ-

- **ပင်မ ကုဒ်ရေးပေးသော ကိုယ်စားလှယ် (coding agent) တစ်ခုကို ရွေးချယ်ပါ** ပြီးလျှင် Week 3–4 ရှိ ပုဂ္ဂိုလ်ရေးဆိုင်ရာ ပြင်ဆင်ဖန်တီးမှု အလုပ်များသည် ပိုမို ထိရောက်ပေါင်းစည်းသွားစေရန် အနည်းဆုံး ငါးပတ်ခန့် ထိုတစ်ခုတည်းကိုပဲ ဆက်လက်အသုံးပြုပါ။ သင့်တော်သော ရွေးချယ်မှုများ- [Claude Code⟦U3⟧ (စာရင်းသွင်းမှု သို့မဟုတ် API key)၊ [OpenAI Codex CLI⟦U4⟧ (open source၊ စာရင်းသွင်းမှု သို့မဟုတ် API key)၊ [Cursor⟦U5⟧၊ [Gemini CLI⟦U6⟧ (open source၊ အခမဲ့သုံးနိုင်သော အဆင့်ပါဝင်သည်) သို့မဟုတ် [opencode⟦U7⟧ (open source၊ သင့်ကိုယ်ပိုင် key ယူဆောင်လာပါ)။
- **မစတင်မီ လစဉ် ကုန်ကျစရိတ် သတ်မှတ်ချက်ကို အသေအချာ သတ်မှတ်ပါ** ပြီးလျှင် သင့် build မှတ်စုများနှင့်အတူ တစ်ပတ်စီ၏ ကုန်ကျစရိတ်ကို မှတ်တမ်းတင်ပါ။ ဤလမ်းညွှန်တွင် ကုန်ကျစရိတ်သည် နောက်မှ စဉ်းစားရမည့်အရာ မဟုတ်ဘဲ ပထမဦးစားပေး တိုင်းတာရမည့် အချက် ဖြစ်သည်။
- **[prompt caching⟦U8⟧ ကို လေ့လာပါ** ပြီးလျှင် လက်အောက်ခံ ကိုယ်စားလှယ် (subagent) များနှင့် စစ်ဆေးခြင်းလုပ်ငန်းစဉ်များအတွက် ပိုမိုဈေးသက်သာသော မော်ဒယ် (model) ကို အသုံးပြုပါ။ ထိန်းမနိုင်သိမ်းမရ ဖြစ်သွားသော ကုန်ကျစရိတ် အများစုသည် လုပ်ငန်းစဉ်စက်ဝန်း တိုင်းတွင် နောက်ခံအချက်အလက် (context) အရှည်ကြီးများကို ထပ်ခါထပ်ခါ ပြန်လည်ပေးပို့ခြင်းမှ လာခြင်းဖြစ်သည်။
- **အခမဲ့ လမ်းကြောင်း-** Hugging Face သင်တန်းများ၊ အထက်ပါ အခမဲ့သုံးနိုင်သော အဆင့်များပါသည့် open-source ကိုယ်စားလှယ် (agent) များ နှင့် ဤလမ်းညွှန်ပါ ဆောင်းပါးတိုင်းသည် ကုန်ကျစရိတ် မရှိပါ။ သင့် builds အတွက် အသုံးပြုသည့် API အသုံးပြုမှုတစ်ခုတည်းသာ ငွေကုန်ကျမည် ဖြစ်သည်။
