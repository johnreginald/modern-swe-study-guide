### Build

သင် အနည်းဆုံး သုံးကြိမ်ပြုလုပ်ခဲ့သော လုပ်ငန်းစဉ် (workflow) တစ်ခုကို ရှာပါ- release notes၊ database migration checks၊ API endpoint scaffolding၊ dependency upgrades သို့မဟုတ် UI ယခင်အလုပ်လုပ်ပြီးသားများ ပြန်လည်ချို့ယွင်းမှု စစ်ဆေးခြင်းများ (UI regression checks)။ ၎င်းကို ကျွမ်းကျင်မှု (skill) တစ်ခုအဖြစ် အောက်ပါတို့နှင့်အတူ ထုပ်ပိုးပါ-

- မော်ဒယ်/ကိုယ်စားလှယ်ကို မည်သည့်အချိန်တွင် အသုံးပြုရမည်ကို ပြောပြသည့် တိုတောင်းသော ⟦C221⟧ တစ်ခု။
- အဆင့်ဆင့် အချက်အလက်ဖော်ပြခြင်း (Progressive disclosure)- ရှားပါးသော အသေးစိတ်အချက်အလက်များကို ချိတ်ဆက်ထားသော ရည်ညွှန်းချက်များတွင် ထားရှိပါ။
- အထက်ပါ CLI လမ်းညွှန်ချက်များကို လိုက်နာသော ရလဒ်သေချာသော စစ်ဆေးမှု (deterministic check) အကူအညီပေးရေး စခရင်ပတ်တစ် ခု။
- စမ်းသပ်ရန် သတ်မှတ်ချက် သို့မဟုတ် နမူနာ ထည့်သွင်းချက် တစ်ခု။
- အောင်မြင်/ကျရှုံး စစ်ဆေးသည့် စိစစ်ရေး ကွန်မန်း တစ်ခု။

၎င်းကို သီးသန့် အသစ်ဖြစ်သော ကိုယ်စားလှယ် အလုပ်လုပ်ချိန် (agent session) မှ ထည့်သွင်းချက် နှစ်ခုပေါ်တွင် စေခိုင်းပါ။ ညွှန်ကြားချက်များ အဓိပ္ပာယ် မရှင်းလင်းသော သို့မဟုတ် နောက်ခံအချက်အလက် လက်ခံနိုင်စွမ်း (context window) ပေါ် ဝန်ပိသွားသော နေရာများကို မှတ်တမ်းတင်ပါ။ ထို့နောက် ဝဘ် ကျွမ်းကျင်မှု တစ်ခု ထည့်သွင်းပါ- သင်၏ အလုပ်လုပ်နေသော အက်ပ်တွင် တစ်ခုခုကို စိစစ်ပေးသည့် ဘရောက်ဆာအခြေပြု စစ်ဆေးမှု (Playwright MCP သို့မဟုတ် Chrome DevTools MCP) တစ်ခု။

### ပြီးစီးမှု သတ်မှတ်ချက်များ (Done when)

- ကျွမ်းကျင်မှုသည် အပို ထပ်ဆောင်း သင်ကြားပေးရန် မလိုဘဲ သီးသန့် အသစ်ဖြစ်သော အလုပ်လုပ်ချိန်မှ ထည့်သွင်းချက် နှစ်ခုပေါ်တွင် မှန်ကန်စွာ အလုပ်လုပ်သည်။
- အကူအညီပေးရေး စခရင်ပတ်တွင် မှတ်တမ်းတင်ထားသော ထွက်ရှိမှု ကုဒ် ရှိပြီး ဆယ်စက္ကန့်အောက် ဖြင့် အလုပ်လုပ်သည်။
- ဝဘ် ကျွမ်းကျင်မှုသည် စစ်မှန်သော ဘရောက်ဆာကို မောင်းနှင်ပြီး သင်၏ အက်ပ်ပေါ်တွင် အောင်မြင်/ကျရှုံး ရလဒ်ကို အစီရင်ခံသည်။
- သင်၏ မှတ်စုများတွင် ⟦C222⟧ ၌ ပြင်ဆင်ခဲ့သော မရှင်းလင်းမှု တိုင်းနှင့် အကြောင်းရင်းကို စာရင်းပြုစုထားသည်။
