## Week 7 — လုံခြုံရေး (Security)

**အဓိကထားမည့်အရာ:** SAST/SCA၊ မှီခိုမှုနှင့် လျှို့ဝှက်ချက် နှင့် ဝင်ရောက်ခွင့်အထောက်အထား (secret / credential) ယိုစိမ့်မှု အားနည်းချက်များ၊ ပရွမ့်ထဲသို့ အန္တရာယ်ရှိကုဒ်ထည့်သွင်းခြင်း (prompt injection) နှင့် ကိုယ်စားလှယ် (agent) သီးသန့် တိုက်ခိုက်နိုင်သော မျက်နှာပြင်များ၊ ကိုယ်စားလှယ် ကူညီပံ့ပိုးမှုဖြင့် ပြဿနာ ခွဲခြားဆန်းစစ်ခြင်းနှင့် ဖြေရှင်းပြုပြင်ခြင်း။

4. **ဗီဒီယို:** Semgrep မှ Isaac Evans၊ [When AI Writes Code: Rethinking App Security⟦U131⟧ (45 min) — AI ဖန်တီးပေးသော အားနည်းချက်များ၊ SAST၊ လုံခြုံရေး ကူညီပံ့ပိုးသူများ၊ တုံ့ပြန်မှု စက်ဝန်းများ နှင့် ကုဒ်ရေးပေးသော ကိုယ်စားလှယ်များ ကြောင့် ဖြစ်ပေါ်လာသော အန္တရာယ်များ။
5. **လက်တွေ့လေ့ကျင့်မှု:** Semgrep၊ [Finding vulnerabilities in modern web apps using Claude Code and OpenAI Codex⟦U132⟧ (20 min) — လက်တွေ့တွင် ကိုယ်စားလှယ် ကူညီပံ့ပိုးမှုဖြင့် ပြဿနာ ခွဲခြားဆန်းစစ်ခြင်း။
6. **ကုဒ်ရေးပေးသော ကိုယ်စားလှယ် ခြိမ်းခြောက်မှုပုံစံ:** OpenAI မှ Fouad Matin၊ [Safety and Security for Code-Executing Agents⟦U133⟧ (14 min) — အဝေးမှ ကုဒ်ပရိုဂရမ် စတင်လိုက်ပါစေခြင်း၊ ပရွမ့်ထဲသို့ အန္တရာယ်ရှိကုဒ်ထည့်သွင်းခြင်း၊ အချက်အလက် ခိုးယူထုတ်ယူခြင်း၊ ကွန်တိန်နာများ၊ ကွန်ရက် ကန့်သတ်ချက်များ၊ လူကိုယ်တိုင် အတည်ပြုချက် (human approval) များ နှင့် OS-အဆင့် ဆန်းဘောက်စ် (sandbox)။
7. **လက်တွေ့လေ့ကျင့်ခန်းများ:** PortSwigger၊ [Web Security Academy⟦U134⟧ — သွယ်ဝိုက်သော ပရွမ့်ထဲသို့ အန္တရာယ်ရှိကုဒ်ထည့်သွင်းခြင်း အပါအဝင် Web LLM attacks လက်တွေ့လေ့ကျင့်ခန်းများကို ပြုလုပ်ပါ (လက်တွေ့လေ့ကျင့်ခန်း နှစ်ခုအတွက် ≈ 60 min)။

### Build

ကိုယ်စားလှယ် လုပ်ငန်းစဉ်စက်ဝန်း (agent loop) တစ်ခုလုံး၏ ခြိမ်းခြောက်မှုပုံစံ (threat model) ကို ဆန်းစစ်ပါ- အသုံးပြုသူ၏ ထည့်သွင်းချက်၊ ရီပို (repository) ပါဝင်အချက်အလက်၊ ရှာဖွေရရှိသော ဝဘ်စာမျက်နှာများ၊ ကိရိယာ (tool) များ၊ လျှို့ဝှက်ချက် နှင့် ဝင်ရောက်ခွင့်အထောက်အထားများ၊ MCP server များ၊ ထုတ်လုပ်ထားသော အမိန့်ပေးချက်များ၊ လော့ဂ် မှတ်တမ်းတင်ခြင်း (logging) များ၊ နှင့် တပ်ဆင်ဖြန့်ကြက်မှု။ အနည်းဆုံး လုပ်ပိုင်ခွင့် (least privilege)၊ တိကျသော ခွင့်ပြုစာရင်း (allowlist) များ၊ လျှို့ဝှက်ချက်များ သီးခြားခွဲထုတ်ခြင်း၊ ဆန်းဘောက်စ် (sandbox) ပြုလုပ်ခြင်း၊ နှင့် ပြန်ပြင်၍မရနိုင်သော လုပ်ဆောင်ချက်များအတွက် လူကိုယ်တိုင် အတည်ပြုချက် (human approval) တို့ကို အသုံးပြုပါ။

SAST (Semgrep သို့မဟုတ် CodeQL)၊ မှီခိုမှု/SCA (OSV-Scanner)၊ နှင့် လျှို့ဝှက်ချက် စကန်ဖတ်မှုများ (gitleaks) ကို CI တွင် စကန်ဖတ်မောင်းနှင်ပါ။ မယုံကြည်ရသော ဖိုင်အချက်အလက်ထဲတွင် အန္တရာယ်မရှိသော သွယ်ဝိုက်သော ပရွမ့်ထဲသို့ အန္တရာယ်ရှိကုဒ်ထည့်သွင်းခြင်း စာကြောင်းကို ထည့်သွင်းထားပြီး၊ ကိုယ်စားလှယ် (agent) က ၎င်းကို ညွှန်ကြားချက်အဖြစ် မဟုတ်ဘဲ အချက်အလက်အဖြစ်သာ သတ်မှတ်ကြောင်း စစ်ဆေးပါ။ လျှို့ဝှက်ချက်များ ပေါက်ကြားမှု၊ အန္တရာယ်ရှိသော ကိရိယာ ထွက်ရှိချက်၊ နှင့် ထိန်းချုပ်မရဘဲ မြင့်တက်သွားသော ကုန်ကျစရိတ် (cost) တို့အတွက် တိုတောင်းသော မမျှော်လင့်သော ပြဿနာရပ် လမ်းညွှန်ချက် စာအုပ်ကို ရေးသားပါ။

### ပြီးစီးမှု သတ်မှတ်ချက်များ

- ခြိမ်းခြောက်မှုပုံစံ စာတမ်းသည် ကိုယ်စားလှယ် လုပ်ငန်းစဉ် တွင် ယုံကြည်ရမှု နယ်နိမိတ်တိုင်းကို နယ်နိမိတ်တစ်ခုစီအတွက် လျှော့ချရေးနည်းလမ်းဖြင့် စာရင်းပြုစုထားသည်။
- SAST၊ SCA၊ နှင့် လျှို့ဝှက်ချက် စကန်ဖတ်မှုများကို CI တွင် မောင်းနှင်ပြီး မြင့်မားသော အန္တရာယ်ရှိ တွေ့ရှိချက်များတွင် တားဆီးသည်။
- ထည့်သွင်းထားသော အန္တရာယ်ရှိကုဒ် စာကြောင်းကို လျစ်လျူရှုထားကြောင်း သက်သေပြနိုင်ပြီး မှတ်တမ်းကို သိမ်းဆည်းထားသည်။
- မမျှော်လင့်သော ပြဿနာရပ် လမ်းညွှန်ချက် စာအုပ်သည် အခြေအနေ သုံးခုလုံးအတွက် တာဝန်ရှိသူ တစ်ဦးစီနှင့် ပထမဆုံး အဆင့် သုံးဆင့်စီကို လွှမ်းခြုံထားသည်။
